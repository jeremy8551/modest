# Modest 编码规范

本文面向参与本仓库开发的人和 AI 智能体，目标是让新增代码与相邻代码在结构、命名、格式及框架使用上保持一致。本文根据根目录 README、Maven 配置，以及工具、表达式、IoC、并发、数据库、脚本引擎和测试代码的代表性样本整理；不表示所有历史代码都已经符合规范。

## 1. 使用规则与约束来源

开始编码前按顺序执行：

1. 阅读当前任务指令、适用的 `AGENTS.md` 和 `~/Documents/workspace/modest-document/开发规范/Java基础开发规范.md`。
2. 阅读 `README.md` 对应功能及“内部设计”章节。
3. 阅读目标模块 `pom.xml`、父 POM、待修改类、直接接口或父类，并至少查看两个相近实现及对应测试。
4. 按本文约定编写最小范围的修改，完成适合本次变更的验证。

“必须”“禁止”是新增、修改代码的要求；“优先”“通常”是根据仓库归纳的惯例。历史代码是实现参照，不自动构成对基础规范的豁免。外部基础规范变更后必须重新阅读，本文不能替代它。发现无法同时满足的约束时，明确说明冲突，不自行修改公共契约或编译目标。

### Java 版本的特别说明

基础规范要求采用 Java 17 特性，但本仓库 README 声明核心兼容 JDK5，根 POM 的 `source/target` 为 `5`；`modest-script-engine`、`modest-spring-boot-starter` 声明为 `6`，`modest-java` 下有 Java 5、6、7、12、16 适配模块。这是需要结合目标模块处理的真实差异。

- 按项目指令使用 `~/.m2/jdks/jdk-17.0.2.jdk` 启动构建。
- Maven 运行 JDK、Toolchains 选择的编译 JDK、源码级别、运行时 API 版本分别检查；使用 JDK17 启动 Maven 不等于所有模块可以使用 Java17 语法。
- 保持现有兼容目标。低版本模块新增代码继续使用显式泛型、普通循环及相邻实现采用的语法，不直接引入 Lambda、Stream、Optional、菱形语法、try-with-resources、record、`var` 或新版本 JDK API。
- 只有目标模块明确支持时才使用相应新语法和 API。不得为了套用新语法修改父 POM、提高模块最低版本或绕过 Toolchains。
- 若任务明确要求在低版本模块采用 Java17 特性，先说明与现有兼容目标的冲突，再确定迁移范围。

## 2. 模块、包与职责

这是脚本引擎及通用工具库，不应把所有代码改造成 Web 应用分层。

| 模块 | 代码归属与开发约定 |
| --- | --- |
| `modest-java` | 按 JDK 版本隔离适配实现 |
| `modest-hutool` | 按 Hutool 版本隔离适配实现 |
| `modest-tool` | 通用工具、集合、基础异常等公共能力 |
| `modest-logger` | 日志抽象、输出及格式化实现 |
| `modest-concurrent` | 线程池、任务执行、协作与定时能力 |
| `modest-expression` | 词法分析、表达式、参数与运算符 |
| `modest-ioc` / `modest-ioc-test` | 容器、组件发现及测试运行支持 |
| `modest-io` / `modest-compress` | 文件流与压缩能力 |
| `modest-os` / `modest-database` | 操作系统抽象与数据库能力 |
| `modest-increment` | 增量处理能力 |
| `modest-script` | 脚本解析、编译、命令执行、会话与变量方法 |
| `modest-script-engine` | JSR 223 标准接口适配 |
| `modest-spring-boot-starter` | Spring Boot 集成 |
| `modest-annotation-processor` / `modest-maven-plugin` / `modest-build` | 注解处理、构建插件与构建支持 |

- 延续目标模块已有的 `cn.org.expect.*` 包名；包名小写、点分隔，不使用下划线。
- 基础规范中的 `cn.org.expect.web` 根包及 `controller -> service -> manager -> mapper` 分层适用于对应 Web 代码，不将现有 `cn.org.expect.script`、`cn.org.expect.util` 等迁移到 Web 包。
- 如果新增 `cn.org.expect.web` 第一层子包，按基础规范增加 `package-info.java`，用一句中文说明职责。
- 按现有职责使用 `command`、`annotation`、`internal`、`impl`、`spi` 等子包，不仅为凑层次新建包。
- 公共接口、默认实现、基类和版本适配各归其位；通用工具不得反向依赖脚本命令或 Starter。新增依赖前检查现有 POM 依赖方向。
- 复用已有能力，禁止在业务类内复制公共工具逻辑，避免引入职责重复的工具库或新的框架。

## 3. 文件与格式

- 使用 UTF-8，新增文本优先使用 LF 换行，文件以换行结束。
- Java 和 XML 缩进使用 4 个空格，禁止 Tab；修改既有文件时避免无关格式化。
- 文件顺序：`package`、空行、JDK/`javax` 等平台导入、空行、项目及第三方导入、空行、类 Javadoc、注解、类声明。
- 同组导入通常按包名排序，优先延续当前文件的分组；不使用通配符，不留未使用导入。
- 无同名类冲突时必须 import 后使用简单类名；仅同名冲突时允许全限定类名。
- 左大括号跟随声明或控制语句，`else`、`catch`、`finally` 与前一个右大括号同一行。
- `if`、`for`、`while` 等控制块使用大括号，即使只有一条语句。
- 关键字与左括号之间一个空格；方法名与左括号之间不加空格；逗号后一个空格；二元运算符两侧留空格。
- 类声明与首个成员之间空一行；方法之间、字段与方法之间空一行。字段按职责分组，通常每个带注释字段独立成段。
- 连续闭合的 `}` 之间不插空行。方法内部按逻辑步骤用一个空行分隔，不连续堆叠空行。
- 单行超过 777 字符必须换行；这不是建议写满的目标。长调用和条件应按逻辑换行，续行延续所在文件的缩进方式。
- 仓库常见数组形式为 `new String[]{"echo", this.message}`，注解数组为 `keywords = {"echo"}`，新增代码沿用这一形式。
- 保留周边长签名、注解和链式调用的现有布局，不运行全仓格式化。

## 4. 命名与成员组织

- 类和接口使用大驼峰，方法、参数、局部变量和实例字段使用小驼峰，常量使用全大写加下划线。
- 方法名以动作或明确语义开头；布尔查询优先用 `is`、`has`、`can`、`should`。
- 沿用已有角色后缀：`Factory`、`Repository`、`Compiler`、`Command`、`Exception`、`Test`；基类常用 `AbstractXxx`，默认实现常用 `DefaultXxx`。不要仅为统一名称重命名公共类。
- 集合名体现元素与容器含义，如 `userList`、`commandMap`、`keywords`；避免 `data`、`obj` 等含义不明的名称。
- 新增变量不使用单字母名称，循环计数器 `i`、`j`、`k` 除外。历史样例中的 `p`、`b1` 不应作为新命名模板。
- 实例字段访问和实例方法调用必须显式使用 `this.`，包括继承的方法；调用父类实现使用 `super.`。静态方法用所属类名调用，静态字段不加 `this.`。
- 仓库常见常量修饰符顺序为 `public final static`；日志字段常见为 `private final static Log log`。沿用目标文件的修饰符顺序，日志名称 `log` 作为已有惯例保留。
- 通常按静态成员、实例字段、构造方法、普通方法组织；访问器、生命周期方法和辅助方法按职责相邻排列，不强制重排既有类。
- 默认收紧可见性，仅供内部使用的成员为 `private`；扩展点需要时使用 `protected`。不得随意改变已有可见性、接口签名、返回码或异常类型。
- Web Service 注入 Mapper 时变量名为 `mapper`，Controller 注入 Service 时使用 `service` 或明确业务名；此要求不扩展为给核心模块添加 Mapper/Controller。

## 5. 中文注释与 Javadoc

- 类、公共 API 和复杂逻辑使用简洁中文说明，注释解释用途、限制和设计原因。
- 类声明及需要说明的方法上方使用多行 `/** ... */`。参数逐项写 `@param`；非 void 方法写 `@return`；声明或约定抛出的异常写 `@throws`，注明触发条件。泛型参数有必要时使用 `@param <T>`。
- 属性注释使用单行 `/** 输出内容 */`，放在属性上方，末尾不加逗号、句号或分号。
- Javadoc 分段使用 `<p>...</p>`，代码使用 `{@code ...}`，类型或成员引用使用 `{@link ...}`。
- 重写方法可不重复父接口注释。历史上有 `/** {@inheritDoc} */`，无需为此全量增删；涉及新增约束时补充必要说明。
- `@Override` 是否可用还需看源码级别，例如 Java5 不支持给接口实现方法使用该注解；遵循模块约束。
- 保留已有作者和时间信息，不伪造 `@author`、`@createtime`；新增类不照抄别人的身份或历史时间。
- TODO/FIXME 格式：`// TODO(v1.1): 支持批量导入`、`// FIXME: 修复空指针问题`。
- 历史代码缺字段注释、缺 Javadoc 标签、裸字段访问或简单字母变量的情况，不作为新增代码的标准。

## 6. 方法实现与基础工具

- 一个方法负责一个清晰动作。参数验证、准备数据、执行操作、返回结果按逻辑组织，复杂分支拆成有意义的方法。
- 优先使用 `cn.org.expect.util` 中已有的 `Ensure`、`StringUtils`、`ArrayUtils`、`IO`、`ResourcesUtils` 等工具；先检查具体方法契约、空值行为及可用版本，不凭名称猜测。
- 参数验证通常放在入口或构造方法，例如 `this.variable = Ensure.notNull(variable);`。为容错返回 `null` 或空集合必须符合原有接口约定。
- 集合判空复用已有统一工具；只有模块已具备对应 Hutool 能力时才使用该适配，不直接新增不兼容的 Hutool 依赖。
- 低版本模块使用显式泛型，如 `new ArrayList<String>()`；遍历优先使用清晰的普通循环或 for-each。需要删除元素时采用迭代器或现有安全方案，禁止在 for-each 中直接修改集合结构。
- 允许使用新版本语法的模块中，Lambda、Stream、Optional 应提升可读性；复杂 Stream 拆为局部变量或方法。
- 延续命令、表达式对象的构造和拷贝契约，涉及 `copy()` 时确认可变子对象是否需要深拷贝；修改 `equals()` 时同时检查 `hashCode()` 契约。
- 不为局部修改引入 Lombok、链式 Builder、大规模函数式改写等新的表达方式。

## 7. 日志、消息和异常

核心模块优先使用项目日志抽象：

```java
private final static Log log = LogFactory.getLog(CurrentClass.class);
```

其中 `CurrentClass` 替换为实际类名，并 import `cn.org.expect.log.Log`、`cn.org.expect.log.LogFactory`。

- 调试输出沿用 `if (log.isDebugEnabled()) { ... }`，尤其避免在日志未启用时计算昂贵参数。
- 日志使用已有消息键或 `{}` 参数形式，检查具体日志 API 后调用；禁止随意改用 `System.out`、`printStackTrace()` 或其他日志门面。
- 面向脚本使用者的输出走 `UniversalScriptStdout`、`UniversalScriptStderr`，从而保留输出重定向和命令执行语义。
- 用户可见消息优先复用模块资源文件 `src/main/resources/cn/org/expect/Messages*.properties`，需要时通过 `ResourcesUtils.getMessage(...)` 解析。
- 消息键延续模块前缀和已有编号方式，例如 `script.stderr.message067`。新增前搜索重名，同步模块已有语言资源并核对参数位置，不为新功能复用语义不一致的键。
- 异常使用现有层次，例如 `ExpressionException`、`DatabaseException`、`UniversalScriptException`。构造方式参照同类异常，保留原始 cause，不把异常静默转换成“成功”。
- 不从历史工具中的宽泛 `catch (Throwable)` 推导出普遍规则；新增捕获范围应与恢复或包装能力一致。
- 不重复打印并层层包装同一个异常；不把密码、令牌或完整敏感连接信息写入日志。

## 8. 资源、IoC 与并发

- 文件流、连接、语句、游标等明确所有权：创建者通常负责关闭，调用方传入的共享资源按接口约定处理。
- 低版本模块沿用 `try/finally` 及 `IO.close(...)`、`IO.closeQuietly(...)`；先确认关闭方法的异常语义，不为省事吞掉业务失败。
- 保持数据库事务提交、回滚及自动提交模式的既有契约。正常路径和异常路径均应释放自己持有的资源。
- 核心组件沿用 `EasyContext`、`@EasyBean`、现有 Factory 或 SPI 扩展机制。仅 Spring 集成代码使用相应 Spring 机制，不为核心库强加 Spring 运行依赖。
- SPI 注册遵循目标模块已有的 `META-INF/services` 或注解处理器方式，不同时维护冲突的注册来源。
- 禁止在普通业务代码中直接 `new Thread()`；复用容器或现有工厂提供的线程池。Spring 场景遵循 README 的线程池复用机制；独立场景沿用 `modest-concurrent` 抽象，不要求启动 Spring。
- 并发修改必须考虑超时、异常传播、共享状态、终止信号、任务上下文与资源归属；已有 `AtomicInteger`、`Terminator`、`EasyCombine` 等机制先阅读再复用。
- 基础线程设施的历史实现不构成在其他模块任意创建线程的理由。

## 9. 脚本引擎扩展

新增命令时，以相近命令及其测试为主要参照，区分编译期与执行期职责：

1. `XxxCommandCompiler` 负责匹配、读取完整语句、解析参数和构造命令；按需要继承 `AbstractTraceCommandCompiler` 等现有模板。
2. 使用 `@EasyCommandCompiler` 配置名称和关键字，核对扫描与注册方式。
3. 复用 `UniversalScriptAnalysis`、`WordIterator` 等解析能力；使用 `assertNext`、`assertOver` 等验证语法，避免另写一套与引擎转义、引号规则不同的字符串切分。
4. `XxxCommand` 负责执行，通过传入的 session、context、stdout、stderr 访问运行环境；根据模板契约实现重定向、回调、后台运行等特性。
5. 返回值 `0` 表示成功，非零状态与引擎错误处理机制保持一致，不能仅打印错误后返回成功。
6. 变量替换、去引号、转义处理的顺序参照相近实现及测试，不能为简化表达随意调整。
7. 新增语法或用户可见行为，同步相应帮助、消息资源和测试。

接口的真实签名以当前源码为准。README 用来理解设计，不直接复制其中可能简写的接口签名。

## 10. 风格示例

以下示例展示新增小类的布局、中文注释、验证、显式泛型与 `this.`，不要求为项目实际增加此类：

```java
package cn.org.expect.script.internal;

import java.util.ArrayList;
import java.util.List;

import cn.org.expect.util.Ensure;

/**
 * 保存按添加顺序排列的命令名称
 */
public class CommandNameList {

    /** 命令名称集合 */
    private final List<String> names;

    /**
     * 初始化命令名称集合
     */
    public CommandNameList() {
        this.names = new ArrayList<String>();
    }

    /**
     * 添加命令名称
     *
     * @param name 命令名称，不能为 null
     * @throws NullPointerException 命令名称为 null
     */
    public void add(String name) {
        this.names.add(Ensure.notNull(name));
    }

    /**
     * 判断是否已经保存命令名称
     *
     * @param name 待查询的命令名称
     * @return 已保存时返回 true，否则返回 false
     */
    public boolean contains(String name) {
        return this.names.contains(name);
    }
}
```

## 11. 测试与构建

- 测试放在目标模块 `src/test/java`，通常与被测类同包，类名使用 `XxxTest`，测试资源放在 `src/test/resources`。
- 抽样代码主要采用 JUnit4 的 `org.junit.Test`、`org.junit.Assert`；新增测试优先跟随同模块风格，不仅因父 POM 包含 Jupiter 就迁移测试框架。
- 使用 `Assert.assertEquals(expected, actual)`、`assertTrue`、`assertFalse` 等验证可观察结果，测试名优先描述行为；不延续历史 `test1`、`test2` 等含义模糊命名。
- 需要容器支持的测试沿用 `@RunWith(ModestRunner.class)`，按已有场景使用 `@RunWithFeature("mysql")`、`@RunWithLogSettings(...)` 等注解；纯单元测试无需额外引入运行器。
- 覆盖本次变更的正常路径、关键边界、异常及资源释放行为，避免只验证内部实现细节或仅打印结果。
- SSH、SFTP、FTP、MySQL、高斯、DB2 等集成依赖按项目要求通过 Docker Compose 启动，连接参数复用测试配置，不硬编码个人环境或真实凭据。
- 先用 `docker compose -f docker-compose.yml config --services` 核对可用服务。当前 SSH 服务配置 SFTP 子系统，独立 `sftp` 服务被注释；当前文件没有高斯服务。不要编造服务名，缺失的依赖须先准备对应配置。

从仓库根目录启动 Maven 的示例：

```sh
export JAVA_HOME="$HOME/.m2/jdks/jdk-17.0.2.jdk"
export PATH="$JAVA_HOME/bin:$PATH"
./mvnw -version
./mvnw -pl modest-expression -am compile
./mvnw -pl modest-expression -am -Dtest=WordIteratorTest -Dsurefire.failIfNoSpecifiedTests=false test
```

以上模块和测试名按实际改动替换。`-am` 同时构建所需上游模块；限定测试时的 Surefire 参数允许上游没有同名测试，不能用它掩盖目标测试未执行，必须检查目标模块报告。

`.mvn/maven.config` 指定 `~/.m2/toolchains-modest.xml`，根 POM 和子模块会选择对应编译 JDK。执行前检查 Toolchains 是否齐备，不能把所有旧版本 JDK 配置简单替换成 JDK17。

集成依赖启动示例（根据测试选择服务）：

```sh
docker compose -f docker-compose.yml up -d ssh ftp mysql db2
```

启动后核对容器健康或服务可连接性、测试 profile、端口和认证配置，再运行对应测试。只改文档时不要求启动容器或执行编译；代码修改必须报告实际运行的验证与未完成的验证，不能把跳过测试描述为通过。
